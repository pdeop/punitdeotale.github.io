I've been building IAM features at AWS for 4 years. I've posted about launches before. But launching features and actually hearing from the people who use them are two very different things.

When you build infrastructure that millions of developers depend on, it's surprisingly easy to end up in a silo. You ship something, you see adoption numbers, maybe you read a few support tickets. But you rarely get to hear directly from the developer who sat down, tried to set up permissions for the first time, and thought: "why is this so hard?"

I want to change that.

I'm starting a blog about making IAM simpler — not the backend systems, but the experience. How do we make security something developers exercise naturally instead of fighting against? I wrote my first post about it here:

[link in first comment]

But more than that, I want to hear from you. If you've used IAM on any cloud platform — what was harder than it needed to be? What made you give up and paste a wildcard policy just to move on? What do you wish someone building these systems knew?

DMs open. Comments open. I'm listening.
